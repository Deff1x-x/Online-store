## 📋 ТЕСТ 1: ЛИЧНЫЙ КАБИНЕТ ПОДПИСЧИКА (CUSTOMER)

### **Сценарий 1.1: Регистрация и первый вход**

**Предусловие:** Новый пользователь, есть интернет

**Шаги:**
```
1. Откры URL магазина (например, store.local/shop/almaty-1)
2. Видишь: "Добро пожаловать, введите телефон"
3. Вводишь: +7 700 123 45 67
4. Получаешь: SMS с кодом (OTP)
5. Вводишь: код из SMS
6. Видишь: форма профиля (Имя, Email, адрес доставки)
7. Выбираешь: адрес из списка (улица, номер дома, подъезд, этаж, квартира, код подъезда)
8. Вводишь: имя, email
9. Нажимаешь: "Продолжить"
10. Видишь: форма оплаты подписки (3900 ₸)
11. Выбираешь: Kaspi QR
12. Сканируешь: QR
13. Платишь: картой
14. Получаешь: SMS "Подписка активирована"
15. Видишь: каталог магазина
```

**Проверочные точки:**
- [ ] SMS доходит (не более 10 сек)
- [ ] OTP экспирирует за 5 минут (потом нужно запросить новый)
- [ ] Адрес выбран из справочника магазина (не произвольный)
- [ ] Подписка активирована (subscription_status = "active")
- [ ] Customer создан в БД с правильным store_id
- [ ] Видно: дата окончания подписки (сегодня + 30 дней)
- [ ] Кабинет открывает каталог автоматически

### **Сценарий 1.2: Заказ с промокодом и доставкой**

**Предусловие:** Подписка активна, есть товары в магазине

**Шаги:**
```
1. Просматриваешь каталог (видны только товары со статусом "available")
2. Добавляешь товары в корзину (3–5 товаров)
3. Видишь: "Товаров на сумму: 8,500 ₸"
4. Нажимаешь: "Оформить заказ"
5. Видишь: 
   - Адрес доставки (предыдущий или добавить новый)
   - Estimated weight: 14 kg
   - Subtotal: 8,500 ₸
   - Online payment amount: 8,075 ₸ (скидка 5%)
   - Delivery fee: 0 (минимум 10,000 ₸)
6. Вводишь: промокод "SUMMER20"
7. Видишь: Real-time validation
   - Если валидный: "Скидка -1,000 ₸ применена"
   - Если невалидный: "Промокод не действителен"
8. Видишь обновленный breakdown:
   - Subtotal: 8,500 ₸
   - First order discount: -500 ₸ (если есть)
   - Promo discount: -1,000 ₸
   - Delivery fee: +500 ₸ (8,500 - 1,500 = 7,000, < 10,000)
   - Final total: 7,500 ₸
   - Online payment: 7,125 ₸
9. Нажимаешь: "Оплатить онлайн"
10. Видишь: Kaspi QR
11. Сканируешь QR, платишь
12. Возвращаешься: в приложение
13. Видишь: "Заказ оформлен, номер #ST001-20251128-0001"
14. Видишь: Статус "Новый, ожидание обработки"
```

**Проверочные точки:**
- [ ] Товары: только со статусом "available"
- [ ] Weight estimation правильная (15 kg = сумма avg_weight товаров)
- [ ] Скидка 5% за онлайн рассчитана правильно
- [ ] Промокод валидируется real-time (< 1 сек)
- [ ] Минимум доставки считается правильно (< 10,000 → +500 ₸)
- [ ] First order discount применен (если это первый заказ)
- [ ] Прромокод можно использовать только 1 раз (если по плану)
- [ ] Итоговая сумма = subtotal - discounts + delivery_fee
- [ ] Online payment amount = final_total × 0.95
- [ ] Заказ в БД создан с правильными статусами (payment_status = "pending" → "online_paid", delivery_status = "new")

### **Сценарий 1.4: Кабинет с POS платежом (вес меняется)**

**Предусловие:** Заказ оформлен, выбрана оплата "При доставке" (POS terminal)

**Шаги:**
```
1. Оформляешь заказ (аналогично 1.2)
2. При checkout: выбираешь "Оплатить при доставке"
3. Видишь: 
   - Final total: 9,000 ₸
   - Payment: "Оплата курьеру на месте"
   - Поле для ввода (не активно, только для информации)
4. Нажимаешь: "Оформить заказ"
5. Видишь: "Заказ создан, курьер заберет оплату"
6. Ждешь: заказ обрабатывается
7. Курьер приезжает с товарами (actual_weight = 16.5 kg, estimate был 15 kg)
8. Рассчитывается: 
   - new_total = 9,000 × (16.5 / 15) = 9,900 ₸
   - topup = 9,900 - 0 = 9,900 ₸ (платишь всю сумму)
9. Видишь на UI позже: order.actual_weight = 16.5 kg, final_total = 9,900 ₸
```

**Проверочные точки:**
- [ ] Для POS платежа: online_payment_amount = 0
- [ ] Вес рассчитывается на основе avg_weight товаров (не произвольно)
- [ ] Пересчет: final_total = subtotal × (actual_weight / estimated_weight)
- [ ] Topup = final_total - online_paid (в этом случае = final_total)
- [ ] После доставки: order.actual_weight и final_total обновлены в кабинете
- [ ] Если actual_weight < estimated_weight, может быть возврат? (clarify logic)

### **Сценарий 2.2: Обработка заказа (pick → measure → delivery)**

**Предусловие:** Заказ со статусом "new" открыт

**Шаги:**
```
1. Нажимаешь: на заказ #ST001-20251128-0001
2. Видишь полный экран заказа:
   - Клиент: Алексей (л/к 205, подъезд 1, код 1234)
   - Товары:
     * Помидоры 2 kg × 500₸ = 1,000₸
     * Молоко 1 л × 200₸ = 200₸
     * Хлеб 2 шт × 150₸ = 300₸
   - Subtotal: 1,500 ₸
   - Estimated weight: 3.5 kg
   - Online paid: 1,425 ₸
   - Status: "new"

3. Видишь кнопку: "Начать комплектацию"
4. Нажимаешь: "Начать комплектацию"
5. Видишь: статус изменился на "picked" (автоматически)
6. Печатаешь: наклейку с адресом и товарами

7. Берешь товары со склада, взвешиваешь на весах
8. Видишь реальный вес: 3.7 kg
9. Нажимаешь на заказ (на экране осталось)
10. Видишь поле: "Фактический вес (kg)"
11. Вводишь: 3.7
12. Нажимаешь: "Сохранить и отправить"
13. Видишь:
    - Статус изменился на "in_delivery"
    - Рассчет: final_total = 1,500 × (3.7 / 3.5) = 1,571.43 ₸
    - Doплата (POS): 1,571.43 - 1,425 = 146.43 ₸
    - На экран выводится: "Сообщить курьеру: доплата 146.43 ₸"

14. Уходит SMS клиенту: "Заказ отправляется, приезд 15:00–17:00"
```

**Проверочные точки:**
- [ ] Переход между статусами: new → picked → in_delivery → delivered
- [ ] Статус обновляется в кабинете клиента (real-time или после refresh)
- [ ] Вес вводится как число (kg), с одной десятичной
- [ ] Пересчет: final_total = subtotal × (actual / estimated)
- [ ] Доплата считается правильно: final_total - online_paid
- [ ] SMS отправляется клиенту при каждом переходе
- [ ] Наклейка печатается с правильными адресом и товарами
- [ ] Если actual_weight < estimated, показать "Переплата 50 ₸" (refund possible?)

- [ ] Изменения цены и статуса видны в каталоге клиента немедленно

## ✅ ОБЩИЕ ЧЕКЛИСТЫ

### **Чеклист: Безопасность (для всех кабинетов)**

- [ ] Логин не хранится в localStorage (только в secure HTTP cookie или Memory)
- [ ] JWT token имеет expiration (1 час для customer, 8 часов для admins)
- [ ] Refresh token хранится securely
- [ ] Нельзя просмотреть чужие заказы (checking store_id и customer_id)
- [ ] Нельзя отправить POS платеж за чужой заказ
- [ ] Rate limiting на auth endpoints (5 попыток в минуту)
- [ ] SQL injection: все inputs валидированы
- [ ] XSS protection: все outputs escaped
- [ ] CSRF tokens на формах (если используется session-based auth)

### **Чеклист: Performance**

- [ ] Список заказов загружается < 1 сек (paginated или indexed)
- [ ] Фильтры работают < 200 мс
- [ ] Картинки товаров оптимизированы (< 100 KB)
- [ ] Infinite scroll не лагает (только 20 items в DOM)
- [ ] API responses < 1 MB

### **Чеклист: UX/Design**

- [ ] Все дата/время в local timezone (не UTC)
- [ ] Currency shown как "₸" или "tenge"
- [ ] Все числа отформатированы (1,500 ₸, не 1500)
- [ ] Кнопки чистые и понятные (не "Submit", а "Создать заказ")
- [ ] Error messages понятные (не "400 Bad Request", а "Минимальная сумма 5,000 ₸")
- [ ] Подтверждение перед опасными действиями (delete, cancel, unsubscribe)
- [ ] Loading spinners при загрузке данных
- [ ] Offline mode graceful handling (или сообщение "No internet")
